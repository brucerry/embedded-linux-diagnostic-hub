## Evidence and stop policy

Successful execution would emit one sanitized diagnostic receipt at most 16 KiB, bound to source/tree/run/attempt/job, source bridge, artifact/activation/Node/npm identities, actual command acknowledgement hashes and the separate parent pair. No token, input body, command output or raw transcript is emitted. Failure uses a different fixed marker with only phase and bounded ownership counters, including preliminary file handles. It cannot be interpreted as a passing receipt. Service metadata must independently confirm the exact run/job/source/attempt and terminal success before accepting the success marker; local environment fields alone do not establish service provenance.

A failure, timeout, denied service/budget, missing receipt, unknown callback/cleanup or uncertain publication stops all later work. No automatic retry, signal, deletion, permission change or forced exit is implemented. A post-admission failure can remain held until the job's 20-minute timeout, even after a failed command has exited, because full retirement was not acknowledged by the complete owner. GitHub disposable runner teardown on timeout/cancellation would not prove graceful descendant retirement. This consequence needs explicit diagnostic execution approval.

No artifact/cache upload or Actions artifact retention is requested. Node/tool/dependency downloads and npm cache/build/input bytes occupy the fresh runner's temporary disk; there is no hard disk quota or cleanup of existing user data. Receipt retrieval is from the specific job log, with its repository retention setting (potentially up to 90 days) and size only known after download. The $0 spending block remains unchanged; no paid runner, budget change, new spend commitment or block bypass is authorized.
