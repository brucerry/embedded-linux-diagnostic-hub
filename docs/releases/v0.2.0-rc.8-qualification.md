# RC8 qualification sign-off

RC8 retains the RC5 application, companion and helper behavior and the subsequent CI startup,
private shared-memory and bounded diagnostic repairs. Its publisher now runs
`npm ci --ignore-scripts` from the existing lockfile before downloading and validating artifacts.
This supplies `fflate`, which the companion source/ZIP validator requires, without running package
lifecycle scripts in the publisher. No dependency version, application behavior, native workload or
release gate changes.

The preceding source `fa5b71d175a0092b6a094dd4f3c4f583d0aa123c` passed main
[Linux/GNOME](https://github.com/brucerry/embedded-linux-diagnostic-hub/actions/runs/38188533330),
[Windows](https://github.com/brucerry/embedded-linux-diagnostic-hub/actions/runs/38188533304) and
[website](https://github.com/brucerry/embedded-linux-diagnostic-hub/actions/runs/38188533535)
checks. Its
[RC7 release workflow](https://github.com/brucerry/embedded-linux-diagnostic-hub/actions/runs/38188533719)
passed version, website, Linux, Windows and all seven GNOME 42/46/48/50 cases. Final asset
validation then stopped with `ERR_MODULE_NOT_FOUND` for `fflate`; notes preparation and publication
were skipped. That failure is a publisher prerequisite omission, not evidence of corrupt assets or a
geometry cure.

- Hosted RC7 GNOME 42 passed 100 native cycles, 100 interrupted cycles, 400 resize requests, exact
  1100-by-760 saved bounds and 411 balanced effects with none remaining. Its 42 ordered PTY ticks
  retained the same PTY, one connection and one terminal channel. All 13,733 protocol rows were
  retained without drops, truncated lines or pending remainder; sampled counters recorded no OOM.
- A clean local publisher control reproduced the same missing dependency. Supplying the already
  present locked `fflate 0.8.3` package let the unchanged full validator pass genuine retained RC5
  assets, including checksums and both ZIPs against source. This is a dependency control, not RC8
  asset qualification or a relabeling of retained RC5 binaries.
- Representative full local GNOME 42 controls passed with and without tracing; a genuine 80-pixel
  mismatch failed the unchanged saved-normal assertion. Finite traced/untraced non-recurrence does
  not prove the historical GNOME 42/48 bounds or GNOME 50 original concurrent-load/cycle31 failures
  cured. Proceeding is within the accepted isolated software scope. Physical GPU/display/device and
  higher GNOME 50 native resource-scale gaps remain outside qualification.

RC5, RC6 and RC7 were not published; their refs and public RC4 remain immutable. The fresh annotated
`v0.2.0-rc.8` tag identifies the new version, publisher repair and this sign-off. Publication
requires RC8's own complete hosted platform/native gates and all 20 release assets with matching
tag/commit, version manifests, checksums and companion source. Windows signing status comes from its
manifest. Release notes use actual published RC4 as their cumulative baseline, excluding unpublished
tags. No local RC8 package build is claimed below the four-GiB build reserve. Cleanup and
physical-device qualification remain separate; no customization implementation is included.
