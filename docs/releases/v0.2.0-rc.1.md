## Diagnostic Hub v0.2.0-rc.1

This preview adds desktop updates with three report options: update without saving, save the report
for later import, or save and automatically reopen it after restart. Updates wait for active
collection, disconnect SSH and never reconnect automatically. Reports are stored in the user's
application data directory; trusted device fingerprints remain available.

The shared desktop and website now include **Reset session data**. It clears the current snapshot
and graph history from RAM, pauses live updates during cleanup and resumes them if previously
enabled. A progress overlay covers the wait and cleanup stages. Reset keeps the current page, the
existing SSH connection and saved report files; the overlay remains through the first fresh snapshot
when live updates are enabled. Paused resets retain the existing cards with unavailable readings
instead of showing a fresh-record guide.

Website authentication supports encrypted private keys through the trusted HTTPS lab gateway. The
fingerprint verification instructions and desktop/web header controls are clearer. The update note
links to the GitHub releases page with an external-window icon.

Snapshot history preparation now runs in a background worker, with a yielding fallback for
restricted browsers. Cached graph calculations reduce repeated work during cursor movement. The
existing collection animation, hover effects, page transitions and copy feedback remain available.
Desktop and web always use full motion, including when the OS requests reduced motion. There is no
animation selector. Process CPU matching uses a PID index, and graph reading options are cached
between cursor events.

Graph views stay available while numeric samples remain in RAM, including when live updates are
paused or SSH is disconnected. Reconnecting appends to the retained history rather than replacing
it; failed connection attempts and report imports preserve earlier samples. Different endpoints have
selectable collection sources, and new SSH connections start separate graph segments and process CPU
baselines. The existing 120-sample window limit remains; reset clears retained history.

The user's live-update selection survives reset and reconnect. When a connected, paused session has
been cleared, selecting a diagnostic collects through the existing SSH connection without reopening
login. LAN attribute warnings preserve valid interface evidence, and collection durations remain
valid if the host's wall clock moves backward.

This is an engineering preview. Clean-machine Windows and Ubuntu/Debian acceptance remain separate
from automated verification; Windows binaries may be unsigned.
