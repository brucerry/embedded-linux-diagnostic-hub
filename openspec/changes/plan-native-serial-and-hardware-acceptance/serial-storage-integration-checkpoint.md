# Serial storage/runner core integration checkpoint

This isolated 12-file packet is based on the independently accepted foundation and five-file seal/payload correction. It is ready for source review and is not adopted into the original application.

The actual FlowRunner and SerialSession now compose through serialCaptureBackend with NativeCaptureStore or IndexedDbCaptureStore. Storage begins before any request is sent. The read loop awaits each original receive observation, preserving its timestamp and raw bytes through bounded repository backpressure. A separate preview consumes at most the first 8192 raw bytes; clipping it does not imply raw capture truncation. The literal prompt detector continues over the full decoded stream with fresh UTF-8/ANSI state per command. Optional prefixed device-time observations use bounded complete lines independently of the preview, preventing a split valid-looking prefix followed by an invalid suffix from being accepted.

The backend awaits flush, full integrity verification and seal before returning. The runner also awaits its result callback before proceeding, permitting the upcoming durable result catalog to acknowledge persistence; that catalog itself is not implemented here. Failure at begin sends nothing; append/quota and seal failures produce explicitly incomplete capture references, pause the flow and suppress later commands. Result-callback failure pauses with the raw capture's existing completeness preserved. Cancellation during a pending receive commit retains ownership until IO settles. Generation changes during asynchronous begin cannot send bytes on a replacement connection.

Qualification: 12 new native integration cases and 53 focused existing runner/Serial/lifecycle cases pass. The large native case feeds more than 32 MiB through the real SerialSession and NativeCaptureStore, then Enter/Enter/script, verifies every capture's generated byte count and SHA-256, exports more than 32 MiB without collecting a Blob/string, and re-arms on the same single port open. Delayed seal/result acknowledgement, begin/append/seal/result failure, cancellation during commit, 8192-byte UTF-8 scripts plus CR/CRLF, oversized observations and changed generations are covered. Nine integration browser cases pass in Chromium/Firefox/Windows Playwright WebKit with real SerialSession/FlowRunner and IndexedDB, full raw hashes, append/seal failures, export size beyond the raw retained payload and reload retention. All 14 actual AutomationPage arming/cancellation regressions pass. Typecheck and focused formatting pass.

The first native log's two failed boundary fixtures used the full script as an over-length step name; names were corrected, and the final complete 12-case run passes. The initial callback typecheck failures were corrected without editing the existing tests: the awaitable callback retains compatibility with synchronous callbacks that return Array.push's number. These earlier logs remain retained.
