# v0.6.0 full-output capture: storage contract before implementation

Status: design and feasibility probes only. The accepted interim Serial/UI checkpoint still has a
64 KiB command cap, 200-row/8 MiB retention and a 32 MiB whole-Blob export limit. None satisfies
this full-output request. No production storage or persistent SSH console code is implemented here.

## Decision and evidence

Use one asynchronous capture repository contract, with native files owned by Electron main on
desktop and bounded IndexedDB binary records in browsers. Use native streaming file export on
desktop and a same-origin service-worker attachment response in browsers. No added dependencies,
external storage service, gateway disk archive or giant Blob/string fallback.

Actual Windows probes wrote and exported 38,797,435 generated bytes in 64 KiB blocks. Every successful
export has SHA-256 `8d65e112c756007d89f552f4f113f4168378a860cb6996d534efa2a2b1353c35`.

The first Chromium probe used an anchor `download` attribute and failed. Ordinary attachment
navigation under the actual nested `/nested/hub/` scope passed in all three engines; use that path.
The worker must be emitted at the site's base directory, without broad scope headers or CSP bypasses.
The existing desktop `app:` scheme needs no service-worker privilege changes because desktop export
uses the trusted bridge. Browser storage support does not add Web Serial support to Firefox/WebKit.

Evidence: `native-storage-feasibility.json`, `indexeddb-streaming-feasibility.json`, their scripts,
logs and retained binary exports in this directory. The initial OPFS failure evidence is retained.
These are generated-data feasibility tests, not integrated capture acceptance or memory profiling.
The repeating test pattern can compress; these results do not establish near-quota capacity,
sustained throughput or uncompressed physical disk consumption.

## Record and commit contract

- `begin`, `append`, `flush`, `finish`, `read`, `page`, `export`, `delete` are asynchronous. An opaque
  capture ID identifies repository-owned data; renderer input never selects a native filesystem path.
  Capture metadata records transport, connection generation, run/step/ordinal, request bytes and
  intent, source clock, completion reason, observed/committed bytes and preview clipping separately.
- Preserve exact raw bytes and every receive observation's timestamp, stream, sequence and byte
  range in the new format. Batch observations into bounded storage blocks; do not reinterpret a
  block as one read. Imported interim captures retain their truthful first/last/count aggregation;
  missing interior observations cannot be reconstructed. Clock jumps preserve sequence order.
- Desktop stores length-framed binary records plus versioned metadata under its installation
  profile, outside ASAR. Use the existing physical-filesystem boundary, exclusive creation and
  regular/unlinked-file checks. Handle short writes, explicit sync/close and interrupted finalization.
  A recoverable committed prefix is distinct from a sealed complete capture.
- Browser IndexedDB stores capture catalog and bounded binary/observation blocks. Commit each batch
  and its committed counters in one transaction; acknowledge transaction completion, not request
  success. Use cursor/index paging, never `getAll()` over captures or output. Origin data remains
  subject to user clearing and eviction unless persistence is granted; no power-loss guarantee.
- Keep processing blocks at most 64 KiB including bounded observation metadata, an application-owned
  pending budget at most 256 KiB, an 8 KiB text preview and 100 visible result rows. These bound RAM,
  not total captured bytes or retained records. No silent 200-row/8 MiB eviction remains in the new
  path. Actual heap acceptance must demonstrate a plateau as total output grows.
- Serial awaits storage backpressure without accumulating promises; SSH pauses/resumes its channel
  around bounded writes. Flush and commit the complete capture before a prompt/exit can authorize
  the next step or repetition. Cancellation invalidates pending arming and storage continuations;
  keep transport/storage ownership until writes and cleanup settle.

## Quota, failures and retention

Before arming, verify a usable store and complete a tiny owned write/commit/read check. Show current
usage/free-space estimates and browser persistence state. Estimates reserve no space. Browser
`persist()` is an explicit user action, not a surprise prompt; denial leaves best-effort storage
clearly labelled. HTTPS/localhost, IndexedDB, service-worker export and required ownership primitives
are feature-probed. Missing/denied APIs disable full capture with a concrete reason; no cap fallback.

On quota/disk-full, partial write, aborted transaction, integrity or storage-worker failure, mark the
capture incomplete with its last committed prefix and failure reason; stop all later sends and
repetitions. If even failure metadata cannot be written, show a persistent in-memory failure alert
and recover the previously unsealed record as interrupted on reopen. Never claim the remote process
stopped or silently resume a flow. Preserve the connected terminal when safe. Queue exhaustion is a
capture failure, not permission to discard bytes.

Retain captures until explicit deletion; display stored bytes, completeness and age. Delete selected
or all retained captures through existing deliberate destructive controls. Hold shared read/export
and exclusive write/delete leases, including across browser tabs; deletion cannot remove an active
capture or export. Cleanup removes only repository-owned IDs, never profiles, preferences or an
arbitrary path. Reopening marks abandoned active captures interrupted; it never replays commands.

## Complete exports and transport integration

Stream JSON/CSV/Markdown/text from the catalog and raw blocks, preserving exact base64 evidence and
receive metadata alongside a separate readable projection. Escape incrementally, preserve existing
CSV formula protections and never build a whole result array/string. Pin a selection/filter snapshot
and committed high-water mark so paging or new rows cannot alter an export. Include incomplete state
and retained-prefix counts. Validate sequence/length integrity before reporting export success.

Desktop main writes a native Save-dialog destination through bounded buffers. Browser uses a
same-origin service-worker response with a short-lived opaque export token bound to its client and
selection; it reads one block at a time and takes an export lease. No remote URL, arbitrary database
or path is accepted. Errors abort the stream and surface incomplete export; browser download handoff
does not prove physical disk flush. Revoke tokens and release leases on completion/cancel/expiry.

Legacy SSH `exec` currently returns one capped JSON capture. Add a negotiated bounded stream for
desktop/gateway capture; browser gateway SSH spools into the browser repository, with original
gateway receive timestamps. Pause on missing acknowledgements and close only the owned channel on
disconnect/failure. Never silently fall back to capped JSON. Persistent SSH console then uses the
same sink and owns a dedicated PTY per flow; existing independent-script mode remains explicit and
unchanged. Normal shell initialization supplies cwd/aliases/functions, with no injected aliases or
profile sourcing. Prompt observation remains independent of preview clipping.

## Reviewable implementation increments and acceptance

1. Repository, frame/schema and streaming exporters: large captures beyond 64 KiB and 32 MiB,
   more than 200 rows, short writes, quota/disk-full injection, crash/reopen, corruption, cleanup and
   overlapping export/delete. All browser engines plus native Electron fixture; bounded-heap test.
2. Wire Serial and independent SSH desktop/gateway into the sink, with storage acknowledgement
   fences and paged results. Test fragmented UTF-8/ANSI, timestamps across clock jumps, Enter-only,
   repeat/cancel/arming/disconnect and storage failure before next send. No physical ports or DUTs.
3. Implement the separate persistent SSH console proposal using this repository, with fixture
   Script/Enter/Enter/Script, cwd and normally initialized alias/function acceptance.
4. Add the separate safe ANSI projection and Serial scene/palette changes, then aggregate review.
   Keep raw evidence intact and request any physical/platform qualification separately.

No dependency decision or hardware access is needed to proceed with these increments. Unknown
browser policies are runtime capability/failure states, not support claims. The target remains
v0.6.0; no version bump, release build, installation, publication or external-device interaction
occurred in these probes.
