## Goals / Non-Goals

Goals: one typed observation/criteria contract, existing session/resource selection, evidence sufficient to reproduce a comparison, and small support envelopes that can grow through reviewed definitions.

Non-goals: user executable plugins, arbitrary commands/scripts/parsers, bus probing, raw sensor protocols, configuration or calibration, destructive/clear-on-read operations, automatic installation/escalation, persistent target services, continuous acquisition or universal domain qualification. Existing LED/UART operations retain their own effect/restoration behavior.

## Decisions

### 0. Remove existing connected-device Python first

The evaluated audit covers all 36 generated collector commands, clock, terminal, discovery/preparation and three adapter compilers shared by desktop/gateway. Only UART executes target Python; discovery optionally invokes its Python/module probe. Treat schema/capability flags, documentation and host fixture callers as associated references, not extra features. Record evidence in docs and retain historical qualification provenance.

Before custom work, remove the live Python probe and Python-based preflight gate, replace UART's Python program with a reviewed installed native serial utility method, and introduce explicit versioned native capabilities. Retain strict version 1 historical inventory/report validation and original profile digests; old Python flags cannot authorize current UART work. Fresh inventory and current reports use a versioned native capability contract, and peers without that contract receive an actionable compatibility error before target testing.

The candidate zero-upload UART method uses an already installed native utility with nonblocking/O_NOCTTY opening and generic ioctl/descriptor handoff, plus installed stty and bounded byte transfer tools. The implementation must preserve TIOCEXCL before configuration/transmit, capture exact original termios, raw 8N1/no-flow-control setup, queue flush, exact UTF-8 byte round trip, bounded cancellation, verified restoration, exclusivity release and owned-handle closure. Native ioctl request codes must follow the observed Linux architecture ABI; unsupported ABI/methods are explicit capability failures. A simple stty/flock or BusyBox microcom replacement is insufficient: advisory lock files do not preserve the existing kernel exclusivity guarantee. No utility, runtime or helper is automatically installed or staged.

The retained DiagnosticHubQualification Alpine VM is Python-free and has BusyBox microcom/stty, but lacks socat and a compiler. Real native-utility UART/PTY qualification therefore currently requires additional controlled test setup or an existing capable test endpoint. Mocked SSH responses and static source checks are useful but cannot substitute for executable UART preservation proof. Keep prerequisite UART/qualification tasks unchecked and do not advance custom implementation until this proof passes. Do not reinstall removed distributions or operate physical hardware. Any new test setup must respect Bruce's existing-resource/no-target-installation restriction and be separately authorized if needed.

### 1. Trusted definitions; customizable intent

Add application-owned definition descriptors under shared/testing and device-side implementations under backend/testing. Each descriptor has an ID, semantic version, content digest, resource-domain compatibility, identity/channel constraints, read semantics, prerequisites, typed parameter schema, parser/conversion versions, freshness support and hard limits. Profiles select these descriptors and customize safe parameters, fixture declarations and acceptance criteria. New adapter IDs driver.measurement and command.measurement dispatch by descriptor compatibility, not a domain-name prefix.

First support slices are reviewed hwmon temperature/voltage/fan scalar inputs, thermal zone temperature, IIO scalar temperature/voltage raw or processed channels, an explicit network-driver carrier descriptor, block.capacity and usb.link-speed descriptors. Availability is conditional on verified ABI/driver semantics and accessible channels; unsupported variants remain visible but unavailable. This is a deliberate cross-domain example, not a promise that every channel with a similar filename works. Driver extensions require source review, unit/protocol evidence and fixtures before registration. The resource model adds storage and usb categories without assigning adapter support merely from their presence. block.capacity records a current block-device capacity using exact declared ABI units, physical/logical device role and generation evidence; it does not open media, mount or issue a self-test. usb.link-speed records the driver-reported connection speed in Mbit/s with USB topology, vendor/product and available serial/interface identity; it does not reset, authorize or send transfers. Missing/invalid speed, hot removal or weak ambiguous identity prevents passing. See proposal.md coverage matrix for initial support versus developer extensions and deferred operations. Both descriptor and command-recipe extension paths are interface-neutral.

The USB connection-speed attribute is documented in the [Linux USB ABI](https://raw.githubusercontent.com/torvalds/linux/master/Documentation/ABI/stable/sysfs-bus-usb); target support still requires reviewed fixtures and driver/kernel evidence. Other storage diagnostics must use their own reviewed contracts; [block statistics](https://docs.kernel.org/block/stat.html) illustrates why field units must be explicit rather than inferred from a disk's physical sector size.

Ship one installed-command recipe, ip.link.rx-packets, for a resolved network interface using an approved absolute ip executable and fixed argv equivalent to ip -j -s link show dev <interface>. Its parser selects one matching interface and an explicitly supported receive-packet counter field; unsupported output versions/fields do not fall back heuristically. Record a counter snapshot in packets, not rate, traffic generation or throughput. Restrict interface arguments to the reviewed grammar; reject option-shaped names unsupported by that grammar. Supported ip versions are registered only with captured parser fixtures and documented command semantics.

Alternative: free command text or profile-provided recipes/parsers. Rejected because review of test intent cannot establish executable safety, resource ownership or deterministic results. No dynamic definition import UI is added.

### 2. Separate physical resource, interface and channel

Extend structural inventory with optional typed identity/provenance and measurement capability records under schema 2. Retain a physical-parent key distinct from an access endpoint and a channel key. Derive evidence from current canonical sysfs topology, DT/ACPI linkage where present, driver and bus-specific observed identifiers; network identity also records namespace context, ifindex and observed address limitations. Class indexes, names, MACs or labels alone are insufficient portable identity.

Resolve current mappings at preparation, immediately before each acquisition, and after reading for identity/metadata continuity. Record the actual runtime path plus identity strength. An explicitly reviewed weak manual mapping lasts only for its current session/boot generation. Reuse the existing one-run reservation and group aliases by physical parent for conflict checks; any driver-bound raw I2C alias remains blocked. Do not claim to coordinate other SSH clients or already-running device programs.

Discovery enumerates metadata and reviewed capabilities only. Measurement values and moving counters are acquired during cases and excluded from plan identity comparison. Inventory remains capped at 2 MiB and 1024 resources, with at most 4096 channel descriptors total; overflow marks incomplete evidence.

Alternative: fixed class paths or global sensor-name lookup. Rejected because renumbering and identical devices can retarget a measurement.

### 3. Explicit conversion and freshness contracts

Represent numeric observations as exact decimal/integer strings with a declared type/unit; reject nonfinite/unsafe values and use exact decimal/rational comparison for scaling and range boundaries. Rendered rounding never changes verdicts. Preserve raw tokens, multiplier/offset inputs, conversion order and ABI/driver provenance. Counters remain exact even beyond JavaScript's safe integer range. No arbitrary expression evaluator is exposed.

For reviewed IIO raw channels use the declared raw/offset/scale contract with channel-specific metadata precedence; absent offset is zero only when the registered ABI/driver contract proves that meaning. Processed input receives only unit conversion. Re-read conversion metadata around acquisition; changes invalidate the observation. Multi-file reads are not claimed to be atomic. Driver faults and missing conversion evidence prevent passing. Board resistor/thermistor conversion and sensor location are not inferred from names.

Linux documentation confirms that hwmon attributes are optional and board conversions can vary ([hwmon ABI](https://docs.kernel.org/hwmon/sysfs-interface.html)). IIO documents raw versus processed channels and scale/offset units ([IIO ABI](https://raw.githubusercontent.com/torvalds/linux/master/Documentation/ABI/testing/sysfs-bus-iio)). Thermal channels use their declared temperature ABI ([thermal ABI](https://raw.githubusercontent.com/torvalds/linux/master/Documentation/ABI/testing/sysfs-class-thermal)). Bind descriptors to the target's supported ABI; latest upstream documentation is not evidence of the target kernel or driver behavior.

Each case explicitly chooses observed-during-case or maximum-source-age freshness. The first judges only the current read and displays unknown physical sample age. The second requires reviewed source-age evidence: capability absence blocks preparation; missing/expired/uncertain evidence during a prepared run is Inconclusive. Record host observation timestamps, monotonic duration, source timestamp/clock domain if available, update interval and uncertainty. Do not use sysfs mtime, repeated equal values or host/device wall-clock subtraction as invented sample timestamps. No IIO triggers or buffer modes are changed to obtain freshness.

Alternative: infer all temperature units from filenames or equate read time with sample time. Rejected because it can create plausible false passes.

### 4. Capability-based execution without mandatory target Python

Use the existing ssh2 execution channel and bounded transport with application-owned fixed POSIX-shell programs. Select only fixture-qualified capability profiles. Do not invoke Python for new driver readings or command recipes, regardless of whether python names version 2, version 3 or is absent. Target-side JSON parsing and engineering arithmetic are unnecessary: the backend builds typed requests, parses finite framed raw evidence, converts exact values and evaluates criteria. The legacy UART Python call is removed in prerequisite phase 0; its verified native serial capabilities remain distinct from driver-reading/recipe capabilities.

Request values enter only validated positional arguments, quoted individually by the backend, plus a small bounded start/cancel control protocol on SSH stdin. The wrapper source and child programs are fixed reviewed application assets whose digest is recorded. Never interpolate profile/device strings into source, eval them, accept returned code or run profile-provided scripts. Reject NUL/control characters and option-shaped parameters outside each descriptor's grammar. Use quoted positional arguments and fixed format strings throughout; recipes cannot select a shell/interpreter. The transport wrapper itself is trusted application code, consistent with existing LED/discovery execution. A reviewed clean environment, absolute prerequisite identities and fixed argv remain required.

**Driver-read capability profile:** installed POSIX sh with tested descriptor redirection, printf, trap/wait and signaling behavior; byte-bounded reads and finite framing (candidate head/od/tr applets); canonical-path and opened-descriptor identity evidence (candidate readlink/stat and /proc fd metadata); boot/process identity; and a qualified independent deadline/termination path. Require the behavior, not a vendor/version label or merely command -v. Use harmless bounded probes of known OS/process objects; perform no bus scan, driver operation, setup write or installation. A profile can use BusyBox applets or other installed equivalents only after their exact syntax/behavior is qualified. Driver reads do not require ip, executable hashing/pinning, GNU timeout, Bash, jq, a compiler or an upload directory.

Read only resolved kernel-owned canonical sysfs attributes under the reviewed resource root. Pin the opened attribute descriptor, verify its canonical source/object against the prepared target before reading, revalidate parent/channel/driver and conversion metadata afterward, and reject hotplug/identity changes. Do not follow arbitrary profile-supplied filesystem paths or use a precheck followed by an unchecked path read. A descriptor profile must prove opened-object identity under its supported trusted-kernel/SSH-account assumptions; if the necessary fd metadata is unavailable or ambiguous, that read is Blocked. No target JSON parser is required: emit bounded, nonce-tagged, length/hex-framed bytes and lifecycle records, then parse them strictly in the backend. Shell integer width never determines sensor/counter precision. Each raw attribute has a small bound (maximum 4096 bytes plus an overflow sentinel); malformed or overlong data cannot be silently truncated into a valid number.

**Command-recipe capability profile:** add the registered installed utility/version, verified native executable object, reproducible fingerprint, descriptor-based executable pinning and supported argv/environment semantics. The reviewed ip recipe requires its supported JSON output; a BusyBox ip lacking those features blocks that recipe while eligible driver readings remain usable. Open and verify the installed native executable, record hash/version/object metadata, invoke the pinned descriptor under the qualified /proc fd-execution profile, and verify identity again afterward. This prevents a pathname replacement from retargeting execution. It does not attest a compromised kernel or protect against a privileged writer changing the same inode in place; such changes invalidate the result when observed, and a contract requiring immutable-byte proof must require that additional capability or be Blocked. Scripts/interpreters, daemonizing utilities, uncontrolled descendants and arbitrary configuration/environment are excluded. Missing hashing or fd execution blocks recipes, not driver reads; do not downgrade to PATH lookup or unchecked check-then-exec.

**Deadline and cancellation profile:** establish an app-owned anchored process group/session with a fixture-qualified setsid/guardian, a proven exclusively owned SSH exec group, or an equivalent installed primitive, an independent remote watchdog, and recorded boot/start/group identities. Do not assume GNU timeout flags or child-group behavior on BusyBox. An installed timeout is used only under its separately qualified semantics; a fixed shell watchdog using supported sleep/signaling is an alternative only when group anchoring, escalation, completion and child cleanup are demonstrated. Host timers/output caps remain independent safeguards. A harmless ownership handshake precedes hardware acquisition: the target emits nonce/start/group evidence; the backend durably records acknowledged ownership before sending bounded GO. Startup handshake expiry never starts a measurement.

Keep the ownership anchor alive until all owned acquisition, command and watchdog children are reaped and group completion is checked. Signal only through the live owned anchor/control path or a qualified SSH signal path; a stale PID plus a read-then-kill check is not sufficient protection against PID reuse. On Cancel, stop future scheduling immediately and interrupt owned work through the qualified path. A driver read may instead finish within its short already enforced per-read deadline while the host records cancellation and prevents another sample. Record the actual cancellation latency/policy; no instantaneous-stop claim is made. Command recipes requiring stronger interruption are unavailable without that capability. Recovery probes may establish absence/completion, but may not kill a reused or unidentified process. Uninterruptible kernel reads and lost acknowledgement remain Inconclusive with unresolved recovery state; closing SSH is not termination proof.

Normal completion requires explicit finite lifecycle records and confirmed owned-child/group completion; timeout/output overflow/interruption never passes. Each driver acquisition has at most a 5-second remote deadline; the backend schedules any repeated samples, so no target-side long-lived sampling loop or fractional sleep implementation is required. New cases retain 1..32 samples, 100..1000 ms host-scheduled intervals, default 5 seconds total acquisition, maximum 25 seconds acquisition plus 5 seconds termination confirmation, 32 KiB command output, 64 KiB case raw evidence, 4 MiB run evidence, 16 MiB reports and the 10-minute run ceiling. Validate feasibility before dispatch. Finite watchdog/reconciliation probes have their own hard bounds; failure to complete is evidence of uncertainty, not permission to retry indefinitely.

**Durable recovery:** the desktop backend or gateway instance owns a bounded crash-safe local ledger. Persist and flush intent before new live measurement dispatch, persist the ownership handshake before GO, and clear unresolved state only after verified completion. Store client/job nonce, hashed connection/target key, observed boot identity and acknowledged group/start identities; exclude credentials, profiles, sensor values and terminal text. Write failure blocks dispatch. Unresolved measurement ownership gates all affected functional tests including legacy adapters, while preserving each verified access method. Startup/reconnect/reset must load and reconcile pending intent before admission. Missing/corrupt state or incomplete process visibility is not proof of release; verified termination, complete qualified absence checks or trustworthy boot-change evidence can recover it. No force-run acknowledgement substitutes for proof. No other client's or unidentified process is signaled. Report export remains explicit; this minimal safety ledger is not automatic report persistence.

**Architecture/OS envelope:** this path executes the board's already installed shell/tools, not a downloaded architecture-specific executable. CPU, word size, endianness, libc and loader therefore do not select a bundled target binary; capability behavior still needs qualification. Cover representative ARM32, ARM64, x86-64 and MIPS metadata/tool profiles in software fixtures without presenting synthetic profiles as physical architecture qualification. Require accessible Linux sysfs/proc evidence, an authenticated SSH exec channel and the specific installed read/ownership/deadline primitives above. Read-only root filesystems and noexec temporary storage are compatible because no target file is uploaded or staged. If SSH policy, proc restrictions, missing applets or installed filesystem execution policy prevents a needed capability, show the exact affected adapter as Blocked. This is not a claim that every Linux board works.

**Alternatives considered:** direct SFTP reads could avoid a shell wrapper, but require a separately qualified file-identity, server deadline and cancellation/recovery contract; the existing testing transport has no such path, so SFTP is not selected for this first increment. Mandatory Python is rejected by Bruce's resolved requirement. Bash/GNU-only wrappers would merely substitute another global burden and are rejected. Host-only timeouts or SSH close cannot prove remote cancellation and are rejected as sufficient lifecycle mechanisms. A copied native helper could supply stronger fd/process APIs, but requires architecture, ABI/loader, permissions and deployment qualification; it is not required, uploaded or implemented in this first increment. Any future optional-helper change must enumerate supported ELF class/machine/endianness and static/libc/kernel ABI, verify release hash/signature and target receipt, obtain explicit consent for the exact temporary location/bytes/execution, respect read-only/noexec/LSM restrictions without remount/chmod escalation workarounds, bound privileges/process lifetime, remove only its owned files and record cleanup failure. It must remain optional: absence leaves independently capable shell paths usable and unsupported methods honestly Blocked. A tool/runtime installation or system service is not a hidden fallback.

The [BusyBox documentation](https://busybox.net/downloads/BusyBox.html) describes configurable applets and differing option sets. Linux documents proc fd/process metadata ([proc filesystem](https://docs.kernel.org/filesystems/proc.html)); [util-linux setsid](https://raw.githubusercontent.com/util-linux/util-linux/master/sys-utils/setsid.c) and [GNU timeout](https://raw.githubusercontent.com/coreutils/coreutils/master/src/timeout.c) provide candidate semantics to qualify, not proof that a target has those implementations. Capability-profile fixtures and process-ownership tests are mandatory acceptance gates for this execution design.

### 5. Versioned profiles, evidence and presentation

Add schema 2 profile/inventory/report types and validators, preserving strict version 1 validators and original canonical digests. Keep legacy adapter verdict rules when reading version 1 history. Version 2 observations form a discriminated scalar union: numeric exact decimal/integer plus an explicit engineering unit, boolean without a numeric unit, or enum token from a registered finite vocabulary. Numeric observations accept numeric ranges only; boolean/enum observations accept matching-type exact equality only. Carrier is boolean, decoded by its reviewed parser from exact 0/1 input; no string truthiness or implicit numeric-to-boolean coercion is allowed. Repeated sampling uses all-samples semantics, not implicit averaging. A valid complete mismatch is Fail. Missing prerequisites/identity are Blocked; parse/freshness/transport/termination uncertainty is Inconclusive; unstarted cancelled work is Skipped. Required cases retain existing aggregate verdict ordering.

Attach structured observations and execution proof to each case. Record profile intent, definition snapshot/digest, parser/conversion versions, resource/channel identity, executable identity/argv, raw and converted samples, criteria, timing/cache limitations and supervision outcome. Historical definition snapshots are bounded declarative data with no executable content and are never conversion authority. Maintain an application-owned data-only historical contract catalog separately from executable registration. Import must match definition/conversion/parser ID, version and digest to a trusted current or retained historical contract, validate permitted metadata sources/units/types, recompute converted values from exact raw inputs and compare criteria under that contract. A self-consistent imported digest or attacker-chosen formula does not establish trust. Reject unknown or mismatched contracts and forged conversion/value/verdict combinations with actionable errors. A removed executable definition remains readable only when its trusted historical semantics remain supported, without becoming executable. Consistency validation never authenticates that observations came from physical hardware; imported reports remain conspicuously claimed historical evidence. Version 1 history retains its original validator and does not gain invented provenance.

Extend existing testing transport feature negotiation so clients learn supported schema versions/measurement definitions before sending schema 2; an older gateway leaves legacy tests usable and explains why new measurements are unavailable. Add guided resource/channel/definition choices and explicit criteria/freshness fields; direct JSON keeps its single Run action. Apply the same source separation, digest/readiness invalidation and visible provenance to both modes. Simulation uses the same contracts with synthetic normal/fault/timeout/cancellation fixtures and no live I/O.

Alternative: add optional fields to schema 1 or silently migrate imports. Rejected because current strict validators reject unknown keys and historical digests/verdicts must remain stable.

## Risks / Trade-offs

- Read-only files can expose side-effectful hardware behavior -> declare ordinary driver-managed acquisition effects; exclude unknown, destructive, clear-on-read and configuration-changing interfaces, with no added control writes.
- Drivers cache samples or expose non-atomic metadata -> report limitations; require reliable age evidence for source-age policy and invalidate changing conversions.
- Strong identity may be unavailable -> explicit current manual mapping with retained weakness; no automatic portable rebinding.
- Remote termination cannot always be confirmed -> non-passing evidence, durable intent and startup/reconnect reconciliation; failed or incomplete recovery remains Blocked.
- Minimal targets may lack individual shell/OS/tool capabilities -> separate driver/recipe capability profiles; no runtime requirement, helper upload or unsafe fallback.
- Shell supervision has implementation-specific signal/group behavior -> qualify anchored ownership, watchdog and completion using deterministic process fixtures; unavailable behavior remains Blocked.
- Local recovery metadata adds persistence -> store only bounded ownership/lifecycle facts, distinct from explicit-export reports, and fail closed on persistence errors.
- Exact comparisons and dual schemas add complexity -> shared typed evaluators, legacy fixtures and forged/inconsistent import tests.
- Command versions vary across distributions -> small fixture-backed support matrix; missing support blocks only that recipe, without package installation.

## Migration Plan

After a separate implementation authorization, add dual-read contracts and feature negotiation first, then discovery/descriptors and execution, then UI/simulation/reporting. Keep legacy APIs/profile/report paths working throughout. Enable durable intent/startup reconciliation before any new measurement can be dispatched; document that rolling back to a version without this recovery contract is unsupported while a target has unresolved work. No rollback path may silently discard recovery state. Export new measurements as schema 2; never downgrade them to schema 1. A rollback to the old application retains stored schema 2 files but cannot execute/render them as supported evidence; retain a compatible application for those files. The registry does not modify the target, so no target migration or setup/restoration phase is required.

Validate with existing software tests plus bounded synthetic SSH fixtures and both UI modes. Physical qualification is separate, only on explicitly authorized available hardware; record exact boards/drivers/tool versions and mark untested support envelopes. Do not reinstall removed qualification distributions or claim simulation as physical acceptance.

## Open Questions

Bruce has resolved the runtime decision: Python must not be mandatory, including on Python-free and Python-2-only boards. This draft recommends capability-qualified fixed shell execution with no helper deployment in the first increment; implementation still requires separate authorization. No additional runtime product decision is deferred. Exact installed-tool capability profiles and board/driver acceptance ranges require fixture or target evidence before they are advertised as supported; absence remains explicit. A future optional native-helper deployment would require its own proposal and consent and is outside this increment.
