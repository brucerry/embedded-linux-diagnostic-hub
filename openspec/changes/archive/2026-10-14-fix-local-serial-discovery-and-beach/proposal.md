## Why

Published v0.5.0 denies a real trusted Electron Serial request because Chromium supplies
app://bundle/ while the policy expects app://bundle. The user reports idle COM11 missing, and
synthetic coverage also exposes truncation after 128 offered ports. The user requested Serial-only
tail removal and a stationary sun with animated pixel flames.

## What Changes

- Accept equivalent root-origin serialization while retaining exact document/main-frame/contents
  checks; test the actual Chromium details and COM11 without opening a physical port.
- Preserve all valid unique runtime-offered IDs and names, without COM-number, brand, USB metadata
  or friendly-name filters; distinguish authorized ports from chooser discovery.
- Remove only the Serial tail and replace solar rotation with gentle edge flames; preserve SSH
  artwork, beach animations, readable terminal text and reduced-motion behavior.
- Record runtime enumeration limits and a safe native-backend follow-up for OS ports the runtime
  cannot expose. Universal arbitrary OS-port support is not claimed by this correction.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- local-serial-terminal: equivalent secure root origins, complete metadata-optional runtime choices,
  stationary sun/fire and Serial-only tail removal.

## Impact

Electron Serial policy/chooser, renderer labels/help, Serial SVG/CSS, focused unit/native/browser
regressions and docs. No dependencies or host permissions change. v0.5.0 tag/assets stay immutable;
the separate live.spec.ts edit and prior archive are preserved. Physical office acceptance is not
authorized in this task and remains unverified.
